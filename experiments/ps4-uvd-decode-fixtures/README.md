# PS4 UVD first-decode reference fixture

This host-only asset prepares a future first-decode comparison. It makes no
PS4/UVD decode claim and changes no driver, build, or live diagnostic source.
`generate.py` uses Python's standard library and existing FFmpeg/ffprobe tools
with libx264 and `trace_headers`; it does not install dependencies.

The input is one synthetic 64 × 64 progressive, 8-bit YUV 4:2:0 frame, with
different horizontal/vertical regions and a small coordinate ramp in every
plane. All samples are generated by the script; there is no acquired image.
The encoder produces Annex B H.264 with SPS/PPS, Constrained Baseline profile,
one I/IDR slice, CAVLC, no B frames and no inter-frame references. Settings
force one encoder thread, disable x264 assembly, select constant-QP encoding,
and remove lookahead and adaptive decisions where configured. The manifest
records the complete argv, executable hashes, tool versions and x264
version/options SEI.

From the `linux-psx` root, select a **previously absent** directory:

```sh
python3 experiments/ps4-uvd-decode-fixtures/generate.py \
  --ffmpeg /opt/homebrew/bin/ffmpeg --ffprobe /opt/homebrew/bin/ffprobe \
  --output ../lab/uvd-2026-10-20/decode-fixtures/run-001
```

On another host, omit the tool arguments to resolve `ffmpeg` and `ffprobe`
through PATH. Python 3.10+ is sufficient. The generator refuses an existing
output path, including an empty directory. A failed attempt keeps its input,
tool logs, generator snapshot and failed manifest; correct the source and use
a fresh numbered output directory. Never replace a failed attempt in place.

The output contains:

| File | Purpose |
| --- | --- |
| `input.yuv420p` | Synthetic uncompressed source: Y then U then V, 6,144 bytes |
| `frame.h264` | Single-frame Annex B input for a future decode test |
| `repeat.h264` | Second independent encode, required to match byte for byte |
| `expected.yuv420p` | Complete FFmpeg software decode, 6,144 bytes |
| `expected.nv12` | Explicit Python byte interleave of decoded U/V, 6,144 bytes |
| `probe.json` | Full stream/frame metadata from ffprobe |
| `headers.stderr.txt` | FFmpeg SPS/PPS/slice header trace |
| `manifest.json` | Tool provenance, argv, NAL offsets/types, hashes, plane statistics, actual checks and limits |
| `generator.py`, `*.stdout.txt`, `*.stderr.txt`, `SHA256SUMS` | Generator snapshot, raw command logs and artifact checksums |

The software decoder processes the whole stream without an output-frame cap;
ffprobe must report exactly one decoded progressive key I frame at 64 × 64.
Annex B framing must contain exactly one SPS, one PPS and one IDR VCL NAL.
Header traces must confirm Baseline constraints, `max_num_ref_frames=0`,
`frame_mbs_only_flag=1`, `entropy_coding_mode_flag=0`, one slice group, and
an I slice starting at macroblock zero. Every decoded plane must be nonuniform
with separated region means, and NV12 deinterleaving must recover the exact
planar bytes. The region-separation check is a fixture sanity check, not a
hardware acceptance tolerance. The output manifest is the record of checks
actually run. Same-host repeat identity does not promise identical encoding
across FFmpeg/x264 versions or builds; preserve this artifact's hashes.

Expected pixels are the **software-decoded output**, since the encode is
lossy. They are not an independent hardware correctness oracle. Future hardware
must compare the visible Y, U and V samples after a documented conversion from
the actual output's stride, crop, tiling and chroma layout. This fixture is
tightly packed: planar Y/U/V offsets are 0/4096/5120 with strides 64/32/32;
NV12 has Y at 0 and byte-interleaved UV at 4096, both with stride 64. Both layouts
have 64 × 64 luma and 32 × 32 samples per chroma plane, with no padding.

No arbitrary pixel tolerance, PSNR threshold, partial-plane comparison or
hardware acceptance count is pre-authorized. Any mismatch needs explanation
and an explicit acceptance decision. A future hardware experiment still needs
the normal bounded UART session, output ownership/completion evidence and its
own acceptance criteria. Nothing has been sent to or decoded on the console
by this fixture work.

The first local generation, on 2026-10-20 with FFmpeg/ffprobe 9.0.2 and x264
core 165 r3222 b35605a, passed all 17 generator checks. Artifacts are in the
workspace's `lab/uvd-2026-10-20/decode-fixtures/run-001/`. The adjacent
`host-checks-001/checks.json` records 28 additional checks: source compilation,
all 22 saved file checksums, refusal of the existing output path with an
unchanged tree, direct FFmpeg NV12 output matching the Python interleave,
lossy source/reference distinction, and the saved generator matching source.
No fixture generation failed. The expected overwrite-refusal invocation
returned 1 and is retained in that check directory. No repository-wide build
or hardware test was run for this asset.
